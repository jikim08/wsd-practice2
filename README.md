## 📂 파일 구성 및 엔지니어링 특징

### 1. `server.js` (Express 백엔드 API)
- **대량 데이터셋**: 1,000건의 인메모리 게시글 데이터 자동 시드.
- **방어적 파라미터 파싱**: `parseInt(..., 10)` 기수 명시, 음수 및 0 페이지 차단, `Math.min(..., 100)` 대량 조회 공격 방어.
- **ORDER BY 화이트리스트 보안**: `SORT_WHITELIST` 객체 매핑으로 SQL Injection 원천 봉쇄 및 `id DESC` 동점자 방지 2차 정렬 결합.
- **2대 페이징 API 제공**:
  - `GET /api/posts`: 오프셋 기반 페이징 (`LIMIT` / `OFFSET`, 표준 `meta` Envelope 응답)
  - `GET /api/posts/cursor`: 고성능 커서 기반 페이징 (`WHERE id < ? ORDER BY id DESC LIMIT 10`, `limit + 1` 패턴으로 `COUNT(*)` 제거)

### 2. `index.html` (SPA 프론트엔드 & 실시간 DevTools 검사기)
- **탭 모드 전환**: [오프셋 번호 페이징] ↔ [커서 기반 무한 스크롤] 즉시 비교.
- **실시간 디바운스 (300ms)**: 연속 타이핑 시 불필요한 API 요청 폭격 방지.
- **AbortController 비동기 방어**: 새 검색어 입력 시 이전 진행 중인 fetch 요청을 즉각 취소하여 Race Condition 버그 예방.
- **브라우저 히스토리 동기화**: `URLSearchParams`와 `history.pushState` 및 `window.onpopstate` 이벤트로 뒤로 가기 / 새로고침 상태 복원 지원.

## 실습 핵심 개념

### ① 오프셋·커서 페이지네이션에 적합한 화면

오프셋은 페이지 번호를 눌러 이동하는 게시판이나 검색 결과 화면에 적합하다. 전체 페이지 수를 보여줄 수 있고, 1페이지에서 5페이지로 바로 이동하는 것도 가능하다.

커서는 SNS 피드처럼 아래로 내리거나 더 보기 버튼을 눌러 글을 계속 불러오는 화면에 적합하다. 마지막으로 받은 글을 기준으로 다음 글을 가져온다. 이 코드에서는 ID 내림차순을 사용하므로, 마지막으로 받은 글보다 ID가 작은 글을 조회한다.

### ② 디바운스·요청 취소의 역할

검색창에 글자를 입력할 때마다 요청을 보내면 요청 횟수가 많아진다. 디바운스는 입력이 끝날 때까지 잠깐 기다렸다가 검색하는 방법이다. 여기서는 마지막 입력 후 300ms 동안 추가 입력이 없으면 요청을 보낸다.

이미 보낸 요청이 있다면 새 검색어를 입력할 때 `AbortController`로 취소한다. 이전 검색의 응답이 늦게 도착해서 새 결과를 덮어쓰는 것을 막기 위해서다. 응답을 받은 뒤에도 `signal.aborted`를 확인하고, 취소 때문에 발생한 `AbortError`는 일반 오류와 구분해서 처리한다.

### ③ `limit + 1` 원리

다음에 보여줄 글이 남아 있는지 확인하기 위해 한 개를 더 조회하는 방법이다. 먼저 검색 조건과 커서 조건에 맞는 글을 고른 다음, `limit + 1`개까지 가져온다.

예를 들어 `limit=3`이면 4개까지 조회한다. 4개가 나오면 다음 글이 있다는 뜻이므로 `hasNext=true`로 설정하고, 응답에는 3개만 담는다. 3개 이하가 나오면 남은 글을 모두 가져온 것이므로 `hasNext=false`가 된다.

```js
const sliced = candidate.slice(0, limit + 1);
const hasNext = sliced.length > limit;
const items = sliced.slice(0, limit);
```

다음 커서는 응답에 담은 마지막 글의 ID로 정한다. 확인용으로 더 가져온 한 개는 다음 요청에서 조회된다. 따라서 전체 글 수를 세지 않아도 다음 결과가 있는지 알 수 있다.

### ④ `offset`·`totalPages` 계산식

`offset`은 앞에서 건너뛸 글의 개수이다. 페이지 번호는 1부터 시작하므로 다음과 같이 계산한다.

```js
offset = (page - 1) * limit;
```

한 페이지에 10개씩 보여준다면 3페이지의 `offset`은 `(3 - 1) × 10 = 20`이다. 정렬된 목록에서 앞의 20개를 건너뛰고 21번째 글부터 가져온다. 실제 코드에서는 페이지 범위를 보정한 `safePage`로 계산한다.

`totalPages`는 검색 결과의 전체 개수인 `totalCount`를 `limit`으로 나눈 뒤 올림한 값이다.

```js
totalPages = Math.ceil(totalCount / limit);
```

검색 결과가 25개이고 한 페이지에 10개씩 보여준다면 총 3페이지가 필요하다. 마지막 페이지에는 5개가 남는다. 이 코드에서는 검색 결과가 없을 때도 1페이지로 표시하도록 아래와 같이 처리한다.

```js
const totalPages = Math.max(1, Math.ceil(totalCount / limit));
```
